# Деньги под защитой — антифрод-прототип (Changellenge × ВТБ)

Решаем проблему клиентов ВТБ, которые теряют деньги из-за мошенничества с социальной инженерией, и проблему банка, который вынужден жёстко блокировать операции «подряд», теряя комиссионный доход, доверие и NPS. Прототип показывает, как многоуровневая реакция (обязательные правила ЦБ + ML-скоринг + адаптивное трение + «Защита близких») снижает хищения **и** долю ошибочных ограничений одновременно.

**Фокус:** переводы физлиц через СБП и ДБО (≈75% денежного объёма хищений у физлиц, II кв. 2026, ЦБ), сценарий социальной инженерии («безопасный счёт», «сотрудник банка/спецслужб»), сегменты: клиенты 55+ и клиенты со сменой номера/новым устройством.

> ⚠️ Данные в демо — синтетические (seed=42), параметры экономики — допущения команды. Условия правил R01–R12 сверены с приказом Банка России № ОД-2506.

## Архитектура блоков

| Блок | Назначение | Вход | Выход |
|---|---|---|---|
| Сбор признаков | Собрать сигналы по операции (в т.ч. с задержкой до суток) | Операция, профиль клиента, базы ЦБ/банка, НСПК | Вектор признаков + флаг `data_lag` |
| Правила R01–R12 | Обязательные признаки ОД-2506 | Вектор признаков, пороги | Список сработавших правил |
| ML-скоринг | Риск операции без сработавших признаков | Вектор признаков | risk_score 0–1 + топ-3 причины |
| Движок решений | Реакция с приоритетом закона | Правила, скор, пороги | пропуск / трение / проверка / приостановка |
| Коммуникация | Понятное сообщение клиенту | Решение, причины | Сообщение в ДБО + шаг подтверждения |
| Очередь оператора | Приоритет ручного разбора | Операции повышенной проверки | Решение оператора |
| «Защита близких» | Независимое подтверждение доверенным лицом | Операция клиента с сервисом | Подтверждение/отклонение (таймаут 12 ч) |
| Обратная связь | Дообучение модели | Исходы разборов, жалобы | Размеченные примеры |

## Запуск

```bash
pip install -r requirements.txt
streamlit run app.py
```

На Windows достаточно двойного клика по `run.bat`. Датасет генерируется автоматически (`python -m src.data_gen` — принудительно). Тесты: `python -m pytest tests -q`.

## Ключевые результаты (синтетика, тест = 18 000 операций)

| KPI | Baseline (только правила) | Наше решение |
|---|---|---|
| Доля предотвращённого объёма хищений | 38% | 76% |
| Доля ошибочно ограниченных законных операций | 3,2% | 1,1% |
| Корректно выявлено (recall) | 89,2% | 96,2% |
| Среднее время трения | 13,8 мин | 1,5 мин |

Экономика (базовый сценарий, допущения в [docs/assumptions.md](docs/assumptions.md)): затраты 50 млн ₽, эффект ≈278 млн ₽/год, ROI ≈456%, NPV (3 г.) ≈574 млн ₽, окупаемость ≈2,2 мес.
